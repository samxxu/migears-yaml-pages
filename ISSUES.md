## P0

### P0-1

- **Status / 状态**: Open
- **Where / 位置**: `src/Compiler.php:74-125`
- **Verification / 验证**: reproduced (`yaml_parse` result)
- **EN**: Duplicate YAML mapping keys are silently last-one-wins[6] and the front end never detects them. A duplicated `sections.content` dropped the first block with no warning and no exception; the same happened for `options.x`, `component.data.k` and a duplicated root `body`. By contrast the XML front end errors out on duplicate `sections`, duplicate `option` values and duplicate `data` keys — a direct violation of this module's core promise not to drop anything silently
- **中文**: YAML 重复映射键被 libyaml 静默「后者胜」[6]，前端全流程无重复键检测。实测 `sections.content` 重复时第一段内容消失且无 warning 无异常；`options.x`、`component.data.k`、根键 `body` 重复同样静默。对照 XML 前端对 `sections` 重名、`option` 重复值、`data` 重复键都显式报错 —— 直接违反本模块「不静默丢弃」的核心承诺

## P1

### P1-1

- **Status / 状态**: Open
- **Where / 位置**: shared layer `migears-pages/src/Compiler.php:199-218`
- **Verification / 验证**: reproduced
- **EN**: Attribute names have no character validation, and quoted YAML keys can express any attribute name (the README sells this): `"data-x y"`, `"x-on:cli ck"` and `"data-x\"y"` all reach the artefact, while the XML side is guarded by `ATTR_NAME_PATTERN`

## P2

### P2-1

- **Status / 状态**: Open
- **Where / 位置**: shared layer `:480-490` vs `migears-xml-pages/src/Compiler.php:157-160`
- **Verification / 验证**: reproduced

- **中文**: section 名不做 trim，与 XML 前端行为分叉：实测 YAML `" content "` 生成 `start(' content ')`，布局里 `<section name="content">` 永远填不上，表现为页面某块静默空白（XML 侧明确 trim 并注明了这个理由）

### P2-2

- **Status / 状态**: Open
- **Where / 位置**: `src/Compiler.php:50-52`
- **Verification / 验证**: static
- **EN**: The `yaml.decode_php` guard does nothing when the current ext-yaml build does not have that directive (`ini_get` returns `false`, so it neither sets nor reports), making the comment's claim of covering "any ext-yaml version" false; there is also no limit on YAML anchor or alias expansion, so a hostile nesting can exhaust memory
- **中文**: `yaml.decode_php` 守卫在当前 ext-yaml 不含该指令时不生效（`ini_get` 返回 `false`，既不 `ini_set` 也不报错），注释声称「无论 ext-yaml 版本次」不成立；另无 YAML 锚点/别名展开上限，恶意嵌套可能耗尽内存

## Test gaps / 测试盲区

Test gaps: duplicate mapping keys (the cause of this module's P0); section names with surrounding whitespace; attribute names with spaces or quotes; reserved loop-variable names; anchor expansion limits. More fundamentally, there is **no cross-verification test for the two front ends that share one contract** — yaml and xml each go their own way, so this class of divergence has no automatic detection at all.

测试盲区：重复映射键（这是本模块 P0 的成因）；section 名带首尾空格；属性名含空格/引号；循环变量保留名；锚点展开上限。更根本的是**缺一套「同契约双前端对拍测试」** —— yaml 与 xml 各自为政，这类分叉没有任何自动发现机制。
