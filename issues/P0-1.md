# P0-1 — The `yaml.decode_php` guard read `(int) $decodePhp !== 0`, which is …

## Finding / 问题

- EN: The `yaml.decode_php` guard read `(int) $decodePhp !== 0`, which is defeated by the alphabetic truthy spellings `On`, `yes` and `true` — `(int) 'On' === 0` — so with `yaml.decode_php=On` a document carrying `!php/object` was deserialised, an object-injection path. Fixed in the working tree by reading the ini through `iniIsEnabled()` (`src/Compiler.php:60`, helper `:172-176`), with `testPhpObjectTagIsNotDeserializedWhateverTruthySpelling` pinning it; the reviewer turned that test red by mutation.
- 中文: `yaml.decode_php` 守卫写的是 `(int) $decodePhp !== 0`，会被字母拼写的真值 `On`、`yes`、`true` 绕过——`(int) 'On' === 0`——于是在 `yaml.decode_php=On` 下，带 `!php/object` 的文档仍被反序列化，构成对象注入路径。工作树中已改为经 `iniIsEnabled()` 读取该 ini（`src/Compiler.php:60`，辅助 `:172-176`），由 `testPhpObjectTagIsNotDeserializedWhateverTruthySpelling` 钉住；评审方以变异让该用例转红。
